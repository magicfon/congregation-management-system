# ADR-0008: 依區域順序顯示回報閒置時間並批量分發

日期：2026-09-20
狀態：已接受

## 決策

使用者指定依地區、區塊及地圖編號順序列出全部地圖，不按閒置天數重排；操作為勾選可分發地圖、選成員、一次分發。採緊湊表格，圖檔按需開啟，使用中項目顯示持有人且不可選取。

後續介面調整：隱藏 A-1／A-2 等中分組標題及分組選取列，改為連續緊湊列；縮小垂直留白，使用中狀態與持有人同列顯示，不改排序及批量分發流程。

閒置時間 = 台北今天日期 − Sheet 區域狀態 E 欄最後完成日。新增 Area.lastReportedCompletedAt，不借用會在收回／重新分發改變的 completedAt 或 lastActivityAt。無日期顯示無回報紀錄；首次同步前顯示待同步。90–179 天黃色、180 天以上紅色，未滿 90 天一般文字，附文字圖例。

Cron 使用同一份完整 213 區狀態表同步 E 欄。提供管理員「更新回報日期」操作，只讀 Sheet 並更新此獨立欄位，不修改 C/D 或既有分配快照；檢查 213 個唯一編號、資料庫對應與日期完整性，錯誤時保留上次資料。空白或公式產生的 0 視為無紀錄；錯誤公式、未來日期或無法解析的值拒絕同步。日期比較統一使用 taipeiDate。E 欄同步失敗記入 cron errors，不中斷既有 C/D 同步。

批量分發 API 僅 admin 可用；使用 serializable transaction 檢查全部地圖與成員，任一已被領取即拒絕整批。成功後批次推送 Sheet C/D 及更新快照；若推送失敗，明確回傳 DB 已分發、Sheet 待同步，不讓使用者重複分發。快照初始必須完整 213 區，才更新其中項目。

既有單張分發 POST 同步補上 admin 限制；閒置統計 API 也採用回報完成日，不再以最後操作時間計算。

沿用舊資料規則：有人員但無分發日視為使用中；已收回且保留人員者可再分發。相同分發／完成時間仍依既有 API 視為使用中，避免不同清單互相矛盾。

部署先新增 nullable 欄位，再執行建置；部署後須驗證登入導向，並以授權 cron 連跑兩次，第二次所有變動計數為零。
