# ADR-0146：我的看板顯示學生通知單確認狀態與內容

2026-11-24，已接受。

## 背景

使用者要求我的看板多一個區塊，列出哪些學生還沒確認收到週中聚會學生委派；管理員也要能看誰已收到、並核對每張通知單內容是否正確（目前尚未人工校驗過）。確認機制沿用 ADR-0090：學生在 LINE 通知單按「收到」，紀錄存在 `settings` 的 `midweek:student-notices:<weekId>`。

## 決策

- 只給管理員：我的看板「管理待辦」下方新增「學生通知單」區塊，資料來自 `GET /api/admin/student-notices`。
- 範圍是今天（台北日期）起已發布、有學生作業的各週，沿用發送名單的計算（`buildPlan`），不另存資料。
- 區塊先列「已發送，未確認」的學生（姓名、日期、節目），標題顯示未確認人數；另一行提示尚未發送、內容已改未重發、需自行轉交或待通知取消的張數，連到週中編排處理。發送仍只在週中編排頁。
- 「核對每張通知單內容」展開後，逐週列出每張通知單上的欄位（姓名、助手、日期、節目、班別）與狀態，已確認的附確認時間。顯示的是目前發布節目算出的內容；狀態「已發送」代表學生收到的與此相同，「內容已改，尚未重發」代表學生手上是舊版。
- 不做「已校驗」標記：管理員核對後若有錯，到週中編排修改並重發即可。

## 後果

- 每次讀看板會為每個未來週讀一次發送紀錄與成員，週數少，成本可忽略。

## 修訂（2026-11-24）

使用者要求精簡：區塊只列「已發送，未確認」與「需自行轉交」的學生（姓名、狀態、日期、節目），已確認的不顯示；移除尚未發送／待處理張數提示與「核對每張通知單內容」展開區塊。
