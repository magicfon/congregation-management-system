# ADR-0102：週中編排版次記錄提交者，草稿一次只給一人編輯

2026-10-30，已接受。

## 背景

使用者要求委派安排（週中編排）的版次要記錄是誰提交的，並且有人提出草稿後，就不能有第二個編輯者。原本所有管理員共用同一份草稿，只靠 `revision` 擋同時儲存，後存的人會看到「其他管理員已更新這週」，但仍可在重新載入後改掉別人的草稿。

## 決策

- **提交者**：發布產生新版次時，在該版次記下發布者姓名（`MeetingVersion.by`，取登入成員的姓名）。版次選單顯示成「第2版・10/20更新・王小明」。舊版次沒有紀錄就不顯示。公開 API 不回傳提交者。
- **草稿鎖定**：管理員按「儲存草稿」、「用這版當草稿」或「從最新手冊重建草稿」後，記下草稿編輯者（`MeetingRecord.draftOwner`：成員 id、姓名、最後儲存時間）。其他管理員在這週只能看：不能儲存、發布、退回版次、重建、刪除後續版本；畫面顯示「某某正在編輯草稿（時間儲存）」，週標題也標「某某編輯中」。
- **解除鎖定**：編輯者發布、按「放棄草稿」（草稿改回目前公開版；已下架則回到最後的版次；沒有任何版次就回到手冊原稿），或把草稿改回與公開版完全相同並儲存。
- **逾時接手**（Claude 預設，使用者可再調）：草稿超過 24 小時沒再儲存，其他管理員會看到「接手草稿」，確認後草稿內容保留、改由自己編輯。未滿 24 小時要先聯絡原編輯者。
- 下架不算編輯草稿，任何管理員都可下架，草稿與鎖定保留。
- 只有尚未儲存的修改不算提出草稿，不鎖定；兩人同時改時仍由 `revision` 擋下後存的一方。

## 取捨

- 鎖定從「儲存」開始而不是一打字就鎖，避免只是點開看、或改了又不存就把別人擋住；代價是兩人可能同時在改未存內容，後存的人會被擋。
- 不另開資料表，鎖定與提交者都存在原本的 `midweek:record:` JSON，舊資料不需轉換；上線前已存在的草稿沒有編輯者，下次有人儲存才開始鎖定。
