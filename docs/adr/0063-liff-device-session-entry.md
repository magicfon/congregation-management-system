# ADR-0063：LIFF 以裝置登入直接進入

日期：2026-10-21；狀態：已接受；調整 ADR-0062。

使用者反映即使沿用 session，仍每次看到登入中且等待過久，並附上重複外觀標頭截圖。使用者明確選擇「直接進入；換帳號時自行登出本站」。

## 決策

- `/liff` 先由伺服器檢查本站 session；有效成員直接導向固定目的頁，不載入 LIFF SDK、不呈現登入介面。繼續透過既有 JWT callback 檢查停用、刪除與 LINE 解除綁定。
- 裝置 session 是本次進入的帳號依據，不每次自動偵測 LINE 帳號切換。更換 LINE 帳號時，使用者先從本站側欄登出，再透過 LINE 選單進入。
- 未登入、過期或已撤銷才顯示 LIFF 驗證入口；保留原 ID token 的伺服器驗證與待管理員連結流程。不延長既有 30 天效期。
- 目的地從 `view` 或 LIFF 的 `liff.state` 還原，但只映射既有固定站內路徑，不能將任意網址當作 redirect。公佈欄為公開頁，直接導向、不讀 session。
- LIFF 入口使用 DashboardLayout 的簡潔入口版型，保留基本內距與全站單一外觀控制，不掛載公佈欄標頭及其 `/api/me` 請求。

## 驗證

隔離測試必須確認有效 session 在伺服器導向、失效 session 仍進驗證、LIFF state 目的地及任意網址防護、公開頁免驗證，並確認實際渲染只有一個外觀控制。手機真實 LINE 的網路耗時與 Cookie 保存仍須實機確認，不能用測試夾具的時間當作正式手機速度。
