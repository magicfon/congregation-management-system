# ADR-0092：週中版次只往前走，可撤回最新版

2026-10-29，已接受。取代 ADR-0053 退回原版號、ADR-0054 獨立刪除後續版本；ADR-0050 其餘版次與高亮規則不變。

## 背景

使用者覺得編排頁的版次管理太複雜。複雜感主要來自「把任一舊版退回成草稿、以原版號發布、保留較高版本」：這條規則帶出草稿基準版、後續版本、發布前確認刪除第N～M版、獨立「刪除後續版本」按鈕及「請先發布第N版才能刪」的限制。

## 決策

- 版次只往前走。目前發布版就是最新版；草稿一律與它比較，發布時建立「發布版＋1」，沒有變更就不能發布。
- 不再提供中間版退回、草稿基準版與刪除後續版本。後端拒絕 `restore`、`delete-later` 動作，不再寫入 `draftBaseVersion`。
- 發錯時在「更多管理」按「撤回第N版」：確認後刪除第N版快照與補填日期，公布欄與草稿回到第N−1版，未發布修改一併捨棄。可連續撤回到第1版為止；下架週次撤回後仍維持下架。撤回帶目前版號並沿用樂觀鎖，過期或並行操作不會多撤一版。
- 舊版改為在「更多管理」唯讀查看，只留「返回編輯」。配色、補填日期、下架與手冊管理維持收合。
- 主畫面狀態列顯示「公開中：第N版」及「有未儲存的修改／有修改尚未發布」；沒有修改時「儲存草稿」與發布按鈕停用，發布按鈕顯示「已發布」。
- 學生 LINE 通知單（ADR-0090）照舊比對已寄出紀錄與目前公開內容；撤回後再按「發送學生通知單」，只通知變動者並對被換掉的人發取消。

## 舊資料

ADR-0053 流程可能留下「公開版低於最高歷史版」的週次。這類週次以公開版為最新版，下次有變更的發布直接接在公開版之後，較高的舊版本及其補填日期一併移除，不再跳確認。

## 驗證

記憶體資料庫測試涵蓋撤回只刪最新版、清除該版日期、公布欄與草稿回上一版、錯誤版號與過期 revision 不寫入、並行撤回只成功一次、連續撤回、第1版不可撤回、下架撤回維持下架、撤回後重新進版及舊流程資料相容。
