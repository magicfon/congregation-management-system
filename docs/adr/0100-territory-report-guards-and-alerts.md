# ADR-0100：區域回報防呆與回報待確認

2026-10-30，已接受。

## 背景

網站內區域回報（ADR-0085）上線後，使用者擔心回報錯地圖會讓別人的地圖被交回，也擔心有人在 Sheet 刪除或修改紀錄後，系統的分配狀態和 Sheet 對不起來卻沒人發現。使用者不要「撤銷回報」，改要防呆與警示：送出前擋下或提醒，送出後由管理員在管理待辦確認。計畫見 Claude Doc「區域回報防呆與警示計畫」。

## 決策

送出前，每個區域依身分分成五種處理，伺服器在送出時重新判斷一次：

| 情況 | 一般成員／未登入 | 管理員 |
| --- | --- | --- |
| 自己領取中的地圖 | 交回（結束日早於領取日則擋下） | 交回 |
| 別人領取中的地圖 | 警示＋勾選確認後送出，不交回，建立「回報待確認」 | 警示後以持有人名義代為回報並交回；結束日早於持有人領取日時只留紀錄 |
| 未領取（已交回或從未派發） | 擋下：「這張地圖目前未領取，請洽管理員」 | 警示後只寫 Sheet 列與完成日 |
| 已有回報待管理員確認 | 擋下：「這張地圖已有人回報，待管理員確認」 | 警示後併入同一則待確認，不交回 |

- 持有人本人回報一律可交回，即使該圖已有別人的回報待確認。那則待確認改為「回報他人地圖（本人已交回）」留在管理待辦，只有「知道了」，讓管理員看到有人可能回報錯號碼。（2026-10-30 使用者確認）
- 未登入者只有在自填姓名與持有人姓名相同時才算本人，永遠不算管理員，畫面也不顯示持有人姓名。
- 確認畫面取代瀏覽器確認視窗，逐區列出「會交回」「不是你領取的，將交管理員確認」等；需要警示的區域必須勾選「我確認這些地圖是我傳道的」才能送出，伺服器也要求這個確認。
- 所有回報都照舊寫入 Sheet「傳道區域回報」一列；Sheet 寫入失敗整筆回滾。

管理待辦的「回報未交回」改為「回報待確認」，收四種提醒（資料表 `report_alerts`，同一區、同一種、同一輪只有一則）：

1. 回報他人地圖：送出時建立。動作：交回、知道了。
2. 回報了卻未交回：每 15 分鐘同步時偵測使用中、但最後完成回報日晚於領取日的地圖。動作：交回、維持使用中。
3. 交回依據已從 Sheet 刪除：回報交回時在 `areas.returnUndo` 記下交回前的持有人、領取日、完成日與觸發回報的結束日；同步時若最後完成回報日退回到該結束日之前就提醒。動作：恢復使用中（還原持有人與原領取日，Sheet C/D 與快照一起改）、維持交回。
4. Sheet C 欄與系統持有人不同：同步時兩邊都改過的衝突，系統照舊以 DB 為準寫回 Sheet，另建提醒。動作：以系統為準、以 Sheet 為準。

「知道了」「維持使用中」等結案後，同一輪不再提醒；有新的回報日或重新派發才會再出現。地圖狀態已變（例如已交回或重新派發）時，同步會把過時的提醒自動結案。每則提醒記錄處理人、時間與處理方式。只在管理待辦顯示，不發 LINE。

同步比對 C 欄時，已交回的地圖視為系統持有人空白（原本拿歷史持有人比較，導致在 Sheet 補回 C 欄會被當成衝突，Sheet 顯示有人持有、系統卻是已交回）。修正後，對已交回的地圖在 Sheet 補回 C 欄，會照「只有 Sheet 改了就以 Sheet 為準」恢復為使用中。

舊 Google 表單的回報匯入同樣比照：表單姓名不是持有人時不交回，改建「回報他人地圖」提醒。

## 取捨

- 不做撤銷回報：回報是 Sheet 上的事實紀錄，錯了由管理員在 Sheet 刪列，系統再提醒交回依據消失。
- 遲交不另處理：沒回報的地圖不會交回，也就不能派給別人；管理員手動收回後才遇到的遲交，由管理員代為回報。
- 回報待確認不交回地圖，持有人照常可用，等管理員判斷。
