# ADR-0140：地圖列表顯示最近回報並可退回

2026-11-22，已接受。

## 背景

使用者要求地圖列表（`/map`）多一欄顯示每區最近的回報，管理員可以「退回」該回報，並把那筆回報在系統裡造成的效果全部還原。回報會影響：Sheet「傳道區域回報」一列、地圖交回（完成時間）與交回前狀態 `returnUndo`、最後完成日（`lastReportedCompletedAt`／Sheet E 欄公式）、系統回報紀錄 `reports`、回報待確認（ADR-0100）、拒訪待審（ADR-0086）、Sheet 區域狀態 C/D 欄與同步快照、個人管理的領取日（ADR-0130）。

## 決策

- 「最近回報」= Sheet「傳道區域回報」中該區送出時間最晚的一列（Google 表單與站內回報都算），顯示姓名與開始–結束日。另一支 API `GET /api/areas/recent-reports` 讀取，不拖慢清單載入；所有登入者看得到，退回按鈕與退回預覽只給管理員。
- 只能退回每區最近的一筆；退回後上一筆變成最近，可再退回。
- 退回前確認視窗列出會發生的事（含是否恢復使用中、最後完成日改成哪天）。按確定後：
  1. 刪除 Sheet「傳道區域回報」那一整列（刪列前重新讀取比對，避免刪錯列）。E 欄公式自動重算。
  2. 若這筆回報讓地圖交回（`returnUndo.endDate` 相同）且之後沒再派發或收回：用交回前狀態恢復使用中（持有人、領取日、完成時間），清除 `returnUndo`，寫回 Sheet C/D 與快照；「交回依據已刪除」待確認一併結案。之後已重新派發或收回的，地圖分配不動並告知。
  3. 個人管理的地圖，退回的是最新一次回報時，領取日改回剩下最新一筆的開始日並寫回 D 欄；沒有更早的回報就不動。
  4. 最後完成日改為剩下回報中最晚的結束日，沒有就清空。
  5. 刪除站內送出留下的系統回報紀錄（同區同期間、送出時間相差 5 秒內）與同次附上的拒訪待審（仍待審的）。
  6. 回報待確認：「回報他人地圖」移除這筆，沒有其他回報就結案；本人交回的那筆被退回時改回「回報他人地圖」；管理員代為回報時順手結案的待確認重新開啟。
- DB 變更與 Sheet 刪列在同一個交易，刪列是最後一步，失敗整筆回滾；C/D 寫入在交易後，失敗交給 cron 推送補救。
- 退回不能復原，要恢復請重新回報。
- 214、215 號（ADR-0139，只寫 Sheet）沒有系統地圖，不在地圖列表上，因此不提供退回。

## 影響

- 新增 `src/lib/report-withdraw.ts`、`GET /api/areas/recent-reports`、`POST /api/territory-reports/withdraw`、`deleteSheetRow()`；檢查腳本 `scripts/check-report-withdraw.cjs`。
- 無資料庫結構變更。

## 修訂（2026-11-22）

使用者更正：不是每列多一欄，而是地圖列表上方多一個「最近回報」區塊，全部地圖的回報依送出時間由新到舊排列，一眼看到距今最近的上一筆是哪天、哪張地圖、誰回報，通常要退回的就是這筆。

- 取消表格裡的「最近回報」欄。
- 區塊先顯示最新 5 筆，可展開到 30 筆；每筆顯示送出時間、地圖、姓名、開始–結束日。
- 退回規則不變：只有該地圖最新的一筆有「退回」按鈕，同一張地圖較舊的回報標示「這張有較新的回報」；214、215 號等沒有系統地圖的標示「沒有系統地圖」。
