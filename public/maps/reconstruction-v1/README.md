# 三張地圖的分區重建草稿

開啟 `index.html` 可切換三張圖、放大、切換候選色塊，點色塊查看編號和問題。也可由本機靜態伺服器開啟 `/maps/reconstruction-v1/index.html`。

## 修正操作與儲存

預覽上方的「補線／調整頂點／儲存修正」可開啟編輯器；正式站的管理員入口是 `/map/boundary-editor`（地圖圖檔頁亦提供入口）。

1. 選取色塊，按「放大選取區」。
2. 「補線切割」：從區塊邊界外逐點畫到另一侧邊界外，按「完成補線」；實際以 2 原圖像素寬切割，保留內洞，新塊重新配對編號。不成功時保留原區塊與正在畫的線。
3. 「調整頂點」：拖曳白色控制點。造成交叉、內洞外移或與鄰區重疊時拒絕變更。提供 20 步復原／重做。
4. 管理員按「儲存到雲端」，寫入 Neon 獨立表 `map_boundary_drafts`；另一裝置登入後自動載入最新版，也可按「載入雲端」。版本衝突時先匯出本機修正，再載入最新版核對，不會強制覆蓋。

本機備份依網站網址與地圖分開保留，**不是雲端儲存**。重新開啟時可按「恢復本機備份」。離線、未登入、權限不足或雲端未部署時仍可匯出／匯入 JSON，但不會顯示雲端儲存成功。匯入需匹配地圖與原圖校驗值，備份版本亦會保留，避免偷偷覆蓋更新。

雲端不修改原始檔、正式 Area polygon 或 Sheet。部署建置會執行 `npm run db:boundary-drafts` 建立獨立資料表；部署後仍需管理員測試儲存、重新開啟與兩裝置版本衝突。套件 polygon-clipping 0.15.7 的 MIT 授權隨附於編輯器 vendor 目錄。

## 檔案格式

- `{mapId}.json`：建議使用的工作格式；明確記錄原圖尺寸、SHA-256、像素座標系、擷取參數、編號位置、問題、候選多邊形。
- `{mapId}.svg`：向量疊圖，用於核對；旁邊的同名 JPG 必須一起保留。
- `{mapId}-mask.png`：擷取的界線遮罩，白線是障礙，不是正式區域。
- `{mapId}.jpg`：原圖的 1500px 預覽，完整解析度原圖仍位於上一層。

JSON 座標為原圖像素 `[x,y]`，原點左上、y 向下。`polygons` 是多塊幾何，每塊的第一個 ring 為外環，後續為洞；每個環首尾相同。不同於舊工具的 `[y,x]`，不可直接載入舊工具。建議待人工核對後另寫轉換器，不直接當正式 areas JSON。

`numberCandidates` 是依圖中文字位置配對的編號，**不是已確認的區域 ID**；`candidateId` 只適用本次抽取，變更參數可能改變。所有候選均為 `needs-review`。保留多部件幾何可容納同一區域分散於不同位置的情況，但目前尚未依編號合併。

## 已知待處理

- 楠梓 1 號未定位；7 號已由原圖放大確認。68 號保留三處標示位置。
- 楠梓 25、89，橋頭 141，梓官 165 的文字定位落在擷取界線上，未配對；需逐張放大確認文字位置與界線。
- 淡紫色線疊在河道、道路、海岸上時顏色改變，仍有漏抓；合併多個編號的候選不能作為正式分區。
- 顏色誤抓與形態學閉合可能產生錯誤小區或跨越不相關線，綠色候選也需人工覆核。接觸圖片邊緣者無法確認完整外界。
- 不用格子或 watershed 強行補滿 213 區。JSON 的 `summary` 列出缺號、未配對及合併組。

## 重現

從 repository 根目錄執行（建議在獨立 Python 虛擬環境，Python 3.12）：

```sh
python -m pip install -r scripts/requirements-map-candidates.txt
python scripts/rebuild-map-candidates.py
```

判讀位置保存在 `scripts/map-label-anchors.json`，以寬 1500px 的預覽像素表示。擷取腳本只寫此草稿目錄，沒有資料庫操作。既有正式 areas JSON 保留原狀。

若未來需要在真實地理底圖呈現，先建立控制點做地理定位，再輸出 GeoJSON；目前像素 JSON + SVG 更適合忠實保留這三張圖片的分區。
